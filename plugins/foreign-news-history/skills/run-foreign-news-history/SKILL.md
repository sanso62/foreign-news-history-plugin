# 외신동향 작업이력 하네스

## 원칙

현재 실행의 증거만 사용한다. 사람 이름, 사람별 작업조·담당, 카테고리 목록, 매체 별칭을 설정이나 코드에 고정하지 않는다. 다만 업무 프롬프트에 명시된 파일 단계별 결과 표기(`1조/국내`, `1조/글로벌`, `1조/오후/총괄`, `2조/보조`, `2조/오전/총괄`, `정기`, `일본문화원`, `순방`)는 사람별 매핑이 아니라 판정 규칙으로 적용한다. 근거가 없으면 추측하지 않고 빈 값과 `확인 필요`를 남긴다.

작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자는 `외신 일일동향`의 `근무` 탭에 있는 `동향 스케줄`을 작업일 요일 기준으로 조회한 결과를 우선 근거로 삼는다. 다만 `근무` 시트의 `구분`과 작업자 이름을 결과 열에 그대로 복사하지 않는다. 근무표는 그날 각 업무를 맡은 사람을 확인하는 근거이고, 결과의 작업조·담당 표기는 현재 파일의 유입 단계와 업무 의미를 해석한 값이다. 시트의 사람 이름이나 사람별 역할은 코드에 복사하지 않고 매 실행 다시 읽는다.

`동향 스케줄`의 셀 주소나 과거 조회 범위를 고정하지 않는다. 매 실행마다 `근무` 탭 메타데이터를 다시 읽고, 현재 그리드를 설정의 `schedule_scan_max_cells` 이하 청크로 나누어 `동향 스케줄` 표 제목을 찾은 뒤 그 아래의 `보고서`·`구분`·요일 헤더를 검증한다. 이전 실행의 셀 주소나 `동향스케줄.json`을 다음 실행에 재사용하지 않는다.

역할 판정의 기본표는 다음과 같다.

- 오후 개별 국내 초안: `1조 / 국내 / <파일명과 근무표가 일치한 작업자>`
- 오후 글로벌 이슈 작업본: `1조 / 글로벌 / <일치 작업자>`
- 오후 취합본: `1조 / 오후/총괄 / <일치 작업자>`
- 오전 보조·개별 초안: `2조 / 보조 / <일치 작업자>`
- 오전 `1차·2차·3차·n차·최종` 총괄본: `2조 / 오전/총괄 / <일치 작업자>`
- 정기 유입: `정기 / 오후/총괄 / <당일 오후 취합 작업자>`
- 일본언론동향 유입: 작업조는 `일본문화원`, 초벌 담당·작업자는 그 기사가 실제로 처음 편집된 당일 작업본에서 별도 판정
- 순방 파일: 작업조는 `순방`, 담당·작업자는 실제 파일 단계와 당일 근무표로 판정
- 최종 대표기사: 최종 담당 `오전/총괄`, 최종 작업자는 당일 오전 총괄 작업자
- 유사보도·완전 미포함 기사: 최종 담당 `최종 보고서 미포함`, 최종 작업자는 동일한 당일 오전 총괄 작업자

## 필수 입력

- 오전 작업 폴더
- 오후 작업 폴더
- 최종보고서 파일
- 같은 작업일의 일본언론동향 원본 파일 경로
- Google Sheets `근무` 탭의 작업일 동향 스케줄

사용자는 오전 작업 폴더, 오후 작업 폴더, 최종보고서, 일본언론동향의 네 경로를 모두 정확하게 입력한다. 작업일은 최종보고서 본문과 파일명에서 자동 판정하며 서로 충돌하거나 판정할 수 없을 때만 사용자에게 확인한다. 비교 파일 경로는 추측하거나 주변 폴더에서 자동 탐색하지 않는다. 출력 폴더만 선택 입력이다.

## 사전 로드

1. 이 스킬 폴더의 `references/workflow-rules.md`와 `assets/harness.config.json`을 읽는다. `workflow-rules.md`는 업무 기준 원문이므로 사용자가 명시적으로 개정을 요청하지 않는 한 수정하지 않는다.
2. `references/schema.md`, `references/run-context.md`, `references/google-sheets.md`를 읽는다.
3. Google Sheets에는 `google-drive:google-sheets`, 엑셀에는 `spreadsheets:Spreadsheets` 스킬을 적용한다. 둘 중 하나가 없으면 대체 구현을 추측하지 말고 필요한 플러그인 설치를 안내한 뒤 중단한다.
4. 로컬 스크립트를 실행하기 전에 Codex 워크스페이스 의존성 경로를 불러온다. 모든 `.py` 파일은 반환된 Python 실행 파일로 실행한다. 모든 `.mjs` 파일은 반환된 Node.js 실행 파일로 실행하고, 반환된 Node.js packages 경로를 해당 명령의 `NODE_PATH`로 설정한다. HWP 판독 모듈은 플러그인에 포함되어 있으므로 사용자의 `olefile` 설치를 요구하지 않는다. 사용자의 Python·Node.js 설치를 가정하거나 전역 환경 변수·프로젝트 `node_modules`를 만들지 않는다.

## 실행

1. 최종보고서 본문과 파일명에서 작업일 후보와 근거를 추출한다.
2. 연결 계정과 스프레드시트를 확인하고 `작업내역`에서 작업일 전날 행만 읽어 `정기작업내역.json`으로 저장한다.
3. 같은 스프레드시트의 메타데이터에서 현재 보이는 `근무` 탭 이름과 그리드 행·열 수를 확인한다. 메타데이터 범위 안을 `schedule_scan_max_cells` 이하의 겹치지 않는 청크로 조회해 `동향 스케줄` 제목 셀을 찾고, 제목 주변의 작은 범위를 다시 읽어 그 아래에 `보고서`·`구분`·작업일 요일을 포함한 요일 헤더가 있는지 검증한다. 표가 없거나 유효한 표가 둘 이상이면 임의 선택하지 않고 중단한다. 확인된 실제 범위를 로컬에 보존하고 `scripts/select_schedule.py`에 조회 범위를 함께 전달해 `동향스케줄.json`을 만든다. 선택 결과에는 표 제목·헤더·보고서·구분·발행 요일·담당자의 현재 원본 셀 주소를 보존하며 사람별 역할 매핑을 만들지 않는다.
4. 사용자가 입력한 네 경로의 존재 여부와 파일 형식을 검사한다. 일본언론동향과 최종보고서의 작업일이 다르면 중단한다.
5. `scripts/discover_context.py`를 `--schedule-json 동향스케줄.json` 및 명시된 일본동향과 함께 실행해 현재 입력의 파일명, 경로, 문서 미리보기, 기사 수, SHA-256과 입력 지문을 `run_context.draft.json`에 수집한다. 최종보고서·작업자 파일·일본동향 중 하나라도 파싱 오류가 있거나 기사 제목이 0건이면 부분 컨텍스트를 저장하지 말고 즉시 중단한다.
6. `discover_context.py`가 현재 파일을 오후 국내 초안, 오후 글로벌 작업본, 오후 취합본, 오전 보조 작업본, 오전 총괄본으로 분류하고 위 역할표를 `run_context.draft.json`에 적용한다. `comparison_stage`는 사용자가 명시한 입력 경로로만 정한다. 작업자는 파일명과 같은 역할의 당일 `근무` 행이 일치할 때만 확정하고, 다섯 역할 열의 판단에는 유효한 `schedule_refs`와 구체적인 `evidence`를 기록한다. 실제 초벌 파일만 `include_unmatched: true`로 표시하며 취합본·중간 총괄본은 제외한다. Codex는 자동 분류와 현재 문서·스케줄을 검수해 충돌만 `unresolved` 또는 실행별 확인값으로 보완한다. 이전 실행 컨텍스트는 복사하지 않는다.
7. 최종보고서의 각 기사는 최초 유입의 시간 순서로 비교한다. 1단계는 Google Sheets `작업내역`의 정기 기사와 사용자가 지정한 일본언론동향 원본, 2단계는 전일 밤 오후폴더, 3단계는 당일 새벽 오전폴더다. 한 단계에서 기준 점수 이상의 후보를 찾으면 뒤 단계의 더 높은 점수나 `priority`가 앞 단계 선택을 덮어쓰지 못한다. 1단계 양쪽에 모두 있으면 정기 경로를 선택하고 `일일일본동향`은 O로 유지한다. 같은 단계 안에서 실제 초안은 취합·총괄본보다 우선한다. 뒤 단계가 선택됐지만 같은 매체·날짜의 1단계 저점수 후보가 있으면 `정기·일본동향 저점수 후보 직접 대조 필요`로 남긴다. 현재 두 원문을 직접 확인한 구체적인 `article_origin_confirmations`만 이 검수를 해소하고 기사별 자동 선택을 교정할 수 있다.
8. 이 스킬 폴더의 `scripts/process_job.py --run-context <경로>`를 실행한다. 별도 설정을 지정하지 않으면 스크립트가 `assets/harness.config.json`을 사용한다. 컨텍스트 작성 후 일본언론동향을 포함한 입력 파일이 바뀌면 중단하고 다시 판단한다.
9. 일본언론동향 원본과 최종 결과를 제목·매체·날짜로 비교한다. 제목이 크게 바뀌었지만 원문상 동일한 기사는 `article_japan_confirmations`에 현재 실행의 원문 대조 근거를 기록해 O로 확정한다.
10. 최종보고서 대표·유사 기사에 실제 초벌 작업본의 완전 미포함(X/X) 기사를 더한 수와 결과 행 수가 같은지 확인한다. 첫 장의 `/` 묶음은 첫 매체를 대표로, 뒤 매체 기사를 유사보도로 유지한다. 유사보도 제목 줄의 날짜가 비어 있으면 매칭된 현재 원본 날짜를 사용한다. 낮은 매칭 점수나 불완전한 역할 근거는 결과에서 제거하지 않고 `확인 필요`로 분리한다. `작업조/초벌 담당` 조합이 선택된 파일의 `source_kind`와 다르면 결과 생성을 실패시킨다.
11. 사용자가 같은 작업일의 권위 있는 정답 파일을 제공하면 `xlsx_to_json.mjs`로 읽은 뒤 `apply_reference_feedback.py`에 현재 `--source-json`도 함께 전달한다. 첫 결과의 유입 경로를 그대로 재확인하지 말고, 기준표의 작업조·초벌 담당·초벌 작업자와 현재 정기·일본·작업본 후보를 다시 대조해 역할·표기·행 순서 차이를 해시 검증된 실행별 확인값으로 만든다. 제목이 전면 수정된 행은 카테고리·매체·날짜·포함 상태가 하나의 행만 가리킬 때 대응시키고, `일일일본동향`의 O와 공란도 기준 파일 해시에 묶어 자동 오탐·누락을 교정한다. 자동 결과에 없는 유사·미포함 행은 정기 JSON·일본동향·`include_unmatched` 작업본의 정확한 현재 원본 후보와 일치할 때만 `article_additions`로 보완한다. 기준 파일 경로와 SHA-256, 현재 원본의 정확한 유입 경로·제목, 삽입 위치, 구체적 행 근거를 모두 기록하고 다른 날짜에는 재사용하지 않는다. 재실행 후 `compare_reference_result.py`의 `exact_match`를 확인한다.
12. `scripts/build_workbooks.mjs`로 `작업이력_중간저장.xlsx`와 `확인필요_목록.xlsx`를 먼저 생성하고 모든 시트를 렌더링 검수한다. 엑셀 생성이 끝나기 전에는 Google Sheets에 쓰지 않는다.
13. `확인 필요` 행을 현재 원문 또는 11단계의 기준표 확인값으로 모두 해소해 `review_rows: 0`인 결과를 다시 만든다. 그 뒤 월별 결과 탭을 읽어 `scripts/sheet_sync_guard.py preflight`를 실행한다. 이 검사는 중간 엑셀 저장 완료와 확인 필요 0건을 강제한다. `append`만 쓰고, `no_op`은 생략하며, `conflict`는 자동 덮어쓰지 않는다.
14. 쓴 범위를 재조회해 `scripts/sheet_sync_guard.py verify`로 완전 일치를 확인한 뒤 `작업이력_최종.xlsx`를 만든다.

## 금지

- 과거 샘플의 사람·조·담당 매핑 재사용
- 파일명 속 사람 이름만으로 작업조·담당까지 확정
- `근무` 시트의 `구분` 또는 작업자 이름을 작업조·초벌 담당·최종 담당 열에 그대로 복사
- `근무` 탭을 읽지 않고 과거 실행의 담당자나 요일 배정을 재사용
- 과거 실행의 `근무` 조회 범위·셀 주소·`동향스케줄.json`을 재사용하거나 `A1:L100` 같은 고정 좌표로 표 위치를 가정
- 비교 파일 경로를 주변 폴더에서 추측하거나 자동 선택
- 오전·오후·최종보고서·일본언론동향 중 일부 경로가 없는 상태로 실행
- 일본언론동향 원본을 찾지 못한 상태에서 일일일본동향을 일괄 X로 확정
- 일본 매체라는 이유만으로 일본동향 O 처리
- 카테고리나 매체명을 고정 사전으로 치환
- 정기·일본동향 → 오후폴더 → 오전폴더의 비교 단계를 실행별 `priority`나 파일명으로 뒤바꾸기
- 근거 없는 값을 빈칸 대신 임의로 채우기
- HWP·HWPX 파싱 실패나 기사 0건을 경고로 낮춰 나머지 파일만으로 계속 처리

- 동일 작업일의 서로 다른 기존 행 자동 교체

## 실행 예시

`<skill-root>`와 `<python-executable>`은 설치된 이 스킬과 Codex 워크스페이스 의존성의 실제 경로로 바꾼다. 결과 폴더를 생략하면 현재 작업 폴더의 `output/<작업일>`에 중간 저장한다.

```powershell
& "<python-executable>" "<skill-root>\scripts\select_schedule.py" `
  --input "근무시트_조회결과.json" --job-date "2026-07-23" `
  --spreadsheet-id "현재 연결에서 확인한 ID" --sheet-name "근무" `
  --range "현재 실행에서 조회한 실제 A1 범위" --heading "동향 스케줄" `
  --output "동향스케줄.json"

& "<python-executable>" "<skill-root>\scripts\discover_context.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --output "run_context.draft.json"

& "<python-executable>" "<skill-root>\scripts\process_job.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --run-context "run_context.json"
```

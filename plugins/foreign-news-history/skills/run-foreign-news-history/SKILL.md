# 외신동향 작업이력 하네스

## 원칙

현재 실행의 증거만 사용한다. 사람 이름, 사람별 작업조·담당, 카테고리 목록, 매체 별칭을 설정이나 코드에 고정하지 않는다. 다만 업무 프롬프트에 명시된 파일 단계별 결과 표기(`1조/국내`, `1조/글로벌`, `오후/오후/총괄`, `2조/보조`, `2조/오전/총괄`, `정기`, `일본문화원`, `순방`)는 사람별 매핑이 아니라 판정 규칙으로 적용한다. 근거가 없으면 추측하지 않고 빈 값과 `확인 필요`를 남긴다.

작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자는 `[VT] 2026년 24시간 외신 모니터링 및 요약 보고`의 `0. 근무 일정` 탭에 있는 `동향 스케줄`을 작업일 요일 기준으로 조회한 결과를 우선 근거로 삼는다. 다만 근무 일정의 `구분`과 작업자 이름을 결과 열에 그대로 복사하지 않는다. 근무표는 그날 각 업무를 맡은 사람을 확인하는 근거이고, 결과의 작업조·담당 표기는 현재 파일의 유입 단계와 업무 의미를 해석한 값이다. 시트의 사람 이름이나 사람별 역할은 코드에 복사하지 않고 매 실행 다시 읽는다.

`동향 스케줄`의 셀 주소나 과거 조회 범위를 고정하지 않는다. 매 실행마다 `0. 근무 일정` 탭 메타데이터를 다시 읽고, 현재 그리드를 설정의 `schedule_scan_max_cells` 이하 청크로 나누어 `동향 스케줄` 표 제목을 찾은 뒤 그 아래의 `보고서`·`구분`·요일 헤더를 검증한다. 이전 실행의 셀 주소나 `동향스케줄.json`을 다음 실행에 재사용하지 않는다.

역할 판정의 기본표는 다음과 같다.

- 오후 개별 국내 초안: `1조 / 국내 / <파일명과 근무표가 일치한 작업자>`
- 오후 글로벌 이슈 작업본: `1조 / 글로벌 / <일치 작업자>`
- 오후 취합본: `오후 / 오후/총괄 / <일치 작업자>`
- 오후 취합본에서 오전 취합본까지 유지됐지만 최종에서 빠진 기사: `1조 / 오후/총괄 / <오후 취합 작업자>`
- 오전 보조·개별 초안: `2조 / 보조 / <일치 작업자>`
- 오전 `1차·2차·3차·n차·최종` 총괄본: `2조 / 오전/총괄 / <일치 작업자>`
- 최신 오전 총괄본에서 처음 확인된 전일자 기사: `1조 / 오후/총괄 / <해당 총괄 작업자>`
- 정기 유입: `정기 / 오후/총괄 / <당일 오후 취합 작업자>`
- 일본언론동향 유입: 작업조는 `일본문화원`, 초벌 담당·작업자는 그 기사가 실제로 처음 편집된 당일 작업본에서 별도 판정
- 순방 파일: 작업조는 `순방`, 담당·작업자는 실제 파일 단계와 당일 근무표로 판정
- 최종 대표기사: 최종 담당 `오전/총괄`, 최종 작업자는 당일 오전 총괄 작업자
- 유사보도·완전 미포함 기사: 최종 담당 `최종 보고서 미포함`, 최종 작업자는 동일한 당일 오전 총괄 작업자

## 필수 입력

- 오전 작업 폴더
- 오후 작업 폴더
- 최종보고서 파일
- Google Sheets `[VT] 2026년 24시간 외신 모니터링 및 요약 보고` 문서 `0. 근무 일정` 탭의 작업일 동향 스케줄

같은 작업일의 일본언론동향 원본 파일 경로는 선택 입력이다. 제공되지 않으면 일본동향 비교를 건너뛰고 결과의 `일일일본동향` 열을 공란으로 유지하며, 누락 자체를 `확인 필요` 사유로 만들지 않는다. 제공된 경우에만 정확한 경로를 사용하고 주변 폴더에서 추측하거나 자동 탐색하지 않는다. 작업일은 최종보고서 본문과 파일명에서 자동 판정하며 서로 충돌하거나 판정할 수 없을 때만 사용자에게 확인한다. 출력 폴더도 선택 입력이다.

## 사전 로드

1. 이 스킬 폴더의 `references/workflow-rules.md`와 `assets/harness.config.json`을 읽는다. `workflow-rules.md`는 업무 기준 원문이므로 사용자가 명시적으로 개정을 요청하지 않는 한 수정하지 않는다.
2. `references/schema.md`, `references/run-context.md`, `references/google-sheets.md`를 읽는다.
3. 입력 Google Sheets 조회에는 `google-drive:google-sheets`, 엑셀 생성에는 `spreadsheets:Spreadsheets` 스킬을 적용한다. 둘 중 하나가 없으면 대체 구현을 추측하지 말고 필요한 플러그인 설치를 안내한 뒤 중단한다. 결과 Google Sheets 쓰기가 비활성화된 동안에는 결과 문서 조회·쓰기 도구를 호출하지 않는다.
4. 로컬 스크립트를 실행하기 전에 Codex 워크스페이스 의존성 경로를 불러온다. 모든 `.py` 파일은 반환된 Python 실행 파일로 실행한다. 모든 `.mjs` 파일은 반환된 Node.js 실행 파일로 실행하고, 반환된 Node.js packages 경로를 해당 명령의 `NODE_PATH`로 설정한다. HWP 판독 모듈은 플러그인에 포함되어 있으므로 사용자의 `olefile` 설치를 요구하지 않는다. 사용자의 Python·Node.js 설치를 가정하거나 전역 환경 변수·프로젝트 `node_modules`를 만들지 않는다.

## 실행

1. 최종보고서 본문과 파일명에서 작업일 후보와 근거를 추출한다.
2. 연결 계정과 입력 스프레드시트 `[VT] 2026년 24시간 외신 모니터링 및 요약 보고`의 메타데이터를 확인한다. `1. 작업 내역`의 실제 행·열 경계 안에서 `A:O`를 5만 셀 이하의 겹치지 않는 유한 범위로 나누고 `FORMATTED_VALUE`로 모두 읽어 원시 응답을 로컬 JSON에 저장한다. `작업날짜`·`작업 조` 같은 선행 열은 보존하고, 헤더명으로 `보도일`과 기사 열을 찾는다. 날짜 문자열 검색으로 행을 고르지 않는다. 특히 ISO 날짜를 `search_spreadsheet_rows`에 넣으면 표시 날짜와 달라 URL에 그 날짜가 든 일부 행만 반환될 수 있으므로 금지한다. 원시 범위 JSON을 `scripts/prepare_source_history.py`에 전달해 표시값을 날짜로 파싱하고 작업일 전날 행만 `정기작업내역.json`으로 저장한다. 출력의 `source_audit`에 입력 문서 ID·`1. 작업 내역`·실제 범위·스캔 행 수·일치 행 수가 남아야 하며 `process_job.py`가 이를 검증한다.
3. 같은 입력 스프레드시트의 메타데이터에서 현재 보이는 `0. 근무 일정` 탭 이름과 그리드 행·열 수를 확인한다. 메타데이터 범위 안을 `schedule_scan_max_cells` 이하의 겹치지 않는 청크로 조회해 `동향 스케줄` 제목 셀을 찾고, 제목 주변의 작은 범위를 다시 읽어 그 아래에 `보고서`·`구분`·작업일 요일을 포함한 요일 헤더가 있는지 검증한다. 표가 없거나 유효한 표가 둘 이상이면 임의 선택하지 않고 중단한다. 확인된 실제 범위를 로컬에 보존하고 `scripts/select_schedule.py`에 조회 범위를 함께 전달해 `동향스케줄.json`을 만든다. 선택 결과에는 입력 문서 ID·탭·표 제목·헤더·보고서·구분·발행 요일·담당자의 현재 원본 셀 주소를 보존하며 사람별 역할 매핑을 만들지 않는다.
4. 오전·오후·최종보고서의 필수 경로와 파일 형식을 검사한다. 일본언론동향 경로가 제공된 경우에만 파일 존재 여부·형식·작업일을 검사하며, 최종보고서의 작업일과 다르면 중단한다.
5. `scripts/discover_context.py`를 `--schedule-json 동향스케줄.json`과 함께 실행하고, 일본동향이 제공된 경우에만 `--japan-input`을 추가해 현재 입력의 파일명, 경로, 문서 미리보기, 기사 수, SHA-256과 입력 지문을 `run_context.draft.json`에 수집한다. 일본동향 미제공 상태는 `not_provided`로 기록한다. 최종보고서·작업자 파일 또는 제공된 일본동향 중 하나라도 파싱 오류가 있거나 기사 제목이 0건이면 부분 컨텍스트를 저장하지 말고 즉시 중단한다.
6. `discover_context.py`가 현재 파일을 오후 국내 초안, 오후 글로벌 작업본, 오후 취합본, 오전 보조 작업본, 오전 총괄본으로 분류하고 위 역할표를 `run_context.draft.json`에 적용한다. `comparison_stage`는 사용자가 명시한 입력 경로로만 정한다. 작업자는 파일명과 같은 역할의 당일 `0. 근무 일정` 행이 일치할 때만 확정하고, 다섯 역할 열의 판단에는 유효한 `schedule_refs`와 구체적인 `evidence`를 기록한다. 실제 초벌 파일만 `include_unmatched: true`로 표시하며 취합본·중간 총괄본은 제외한다. Codex는 자동 분류와 현재 문서·스케줄을 검수해 충돌만 `unresolved` 또는 실행별 확인값으로 보완한다. 이전 실행 컨텍스트는 복사하지 않는다.
7. 최종보고서의 각 기사는 최초 유입의 시간 순서로 비교한다. 1단계는 입력 스프레드시트 `1. 작업 내역`의 정기 기사와, 제공된 경우에만 사용자가 지정한 일본언론동향 원본이다. 2단계는 전일 밤 오후폴더, 3단계는 당일 새벽 오전폴더다. 자동 일치 기준에 도달한 1단계 후보는 뒤에서 복사된 개별 초안보다 우선한다. 1단계 후보가 자동 기준 미만일 때만, 자동 기준 이상의 현재 개별 국내·글로벌 초안이 `ambiguity_margin` 이상 강하면 기사 단위의 직접 초벌 근거로 선택한다. 1단계 후보가 검수 기준에도 못 미치고 개별 초안은 검수 기준 이상이면서 같은 여유폭 이상 우세하면 낮은 점수 경고 없이 명확한 초안 유입으로 확정한다. 일본동향이 제공됐을 때 동률·근소한 차이는 정기·일본 순서를 유지한다. 1단계 양쪽에 모두 있으면 정기 경로를 선택하고 `일일일본동향`은 O로 유지하되, 제목이 크게 바뀐 일본 원문을 현재 실행에서 직접 확인한 `article_japan_confirmations`는 정기 추정 대신 일본 원문을 최초 유입으로 확정한다. 같은 단계 안에서 실제 초안은 취합·총괄본보다 우선한다. 뒤 단계 취합·총괄본이 선택됐지만 같은 매체·날짜의 1단계 저점수 후보가 있으면 `정기·일본동향 저점수 후보 직접 대조 필요`로 남긴다.
8. 이 스킬 폴더의 `scripts/process_job.py --run-context <경로>`를 실행한다. 일본동향이 제공된 경우에만 `--japan-input`을 추가한다. 별도 설정을 지정하지 않으면 스크립트가 `assets/harness.config.json`을 사용한다. 컨텍스트 작성 후 입력 파일이 바뀌면 중단하고 다시 판단한다.
9. 일본언론동향이 제공된 경우에만 원본의 모든 기사와 최종 결과를 제목·매체·날짜로 전수 비교한다. 제목 점수가 낮아도 같은 매체이고 날짜가 하루 이내인 후보는 반드시 두 원문을 직접 확인한다. 동일 기사면 `article_japan_confirmations`에 현재 실행의 원문 대조 근거를 기록해 O로 확정한다. 일본동향의 초벌 담당·작업자는 기사별 우연한 첫 매치가 아니라 일본동향 전체 묶음을 가장 완전하게 취급한 당일 작업본과 근무표로 판정한다. 일본동향이 제공되지 않으면 이 단계를 건너뛰고 `일일일본동향` 열을 공란으로 둔다.
10. 최종보고서 대표·유사 기사에 실제 초벌 작업본의 완전 미포함(X/X) 기사와 오후 취합본에서 오전 취합본까지 유지된 완전 미포함 기사를 더한 수가 결과 행 수와 같은지 확인한다. 첫 장의 `/` 묶음은 첫 매체를 대표로, 뒤 매체 기사를 유사보도로 유지하되, 묶음 대표 제목은 첫 본문 기사와 의미상 대응할 때만 덮어쓴다. 최신 오전 총괄본에 명시된 유사보도가 최종 본문 추출에서 빠졌으면 같은 묶음의 대표 기사 뒤에 자동 복구한다. 최신 총괄본의 카테고리는 최종 상위 카테고리의 호환되는 확장 표기일 때만 반영한다. 유사보도 제목 줄의 날짜가 비어 있으면 매칭된 현재 원본 날짜를 사용한다. 낮은 매칭 점수나 불완전한 역할 근거는 결과에서 제거하지 않고 `확인 필요`로 분리한다. `작업조/초벌 담당` 조합이 선택된 파일의 `source_kind`와 다르면 결과 생성을 실패시킨다.
11. 사용자가 같은 작업일의 권위 있는 정답 파일을 제공하면 `xlsx_to_json.mjs`로 읽은 뒤 `apply_reference_feedback.py`에 현재 `--source-json`도 함께 전달한다. 첫 결과의 유입 경로를 그대로 재확인하지 말고, 기준표의 작업조·초벌 담당·초벌 작업자와 현재 정기·일본·작업본 후보를 다시 대조해 역할·표기·행 순서 차이를 해시 검증된 실행별 확인값으로 만든다. 제목이 전면 수정된 행은 카테고리·매체·날짜·포함 상태가 하나의 행만 가리킬 때 대응시키고, `일일일본동향`의 O와 공란도 기준 파일 해시에 묶어 자동 오탐·누락을 교정한다. 자동 결과에 없는 유사·미포함 행은 정기 JSON·일본동향·`include_unmatched` 작업본의 정확한 현재 원본 후보와 일치할 때만 `article_additions`로 보완한다. 기준 파일 경로와 SHA-256, 현재 원본의 정확한 유입 경로·제목, 삽입 위치, 구체적 행 근거를 모두 기록하고 다른 날짜에는 재사용하지 않는다. 재실행 후 `compare_reference_result.py`의 `exact_match`를 확인한다.
12. `scripts/build_workbooks.mjs`로 `작업이력_중간저장.xlsx`와 `확인필요_목록.xlsx`를 먼저 생성하고 모든 시트를 렌더링 검수한다.
13. `확인 필요` 행을 현재 원문 또는 11단계의 기준표 확인값으로 모두 해소해 `review_rows: 0`인 결과를 다시 만든다. 현재 원문 확인값은 반드시 실행 컨텍스트에 기록하고 `process_job.py`를 재실행한다. 생성된 `result.json`·내부 동기화용 `google_payload.json`·엑셀을 손으로 서로 다르게 고치지 않는다. 특히 `article_japan_confirmations`로 일본 원문 유입이 확정된 행은 정기 후보의 원시 점수가 더 높더라도 스크립트가 선택한 `일본문화원` 유입 역할을 다시 정기로 바꾸지 않는다. 결과가 잘못됐다고 판단하면 확인값을 수정해 처음부터 재처리한다.
14. `review_rows: 0`을 확인한 뒤 `scripts/build_workbooks.mjs --final`로 `작업이력_최종.xlsx`를 만들고 모든 시트를 렌더링 검수한다. `checkpoint.json`이 `phase: excel_finalized`, `excel_finalized: true`인지 확인하면 기본 실행을 완료한다.
15. 기본 설정 `sync.google_sheets_write_enabled: false`에서는 결과 스프레드시트 `[VT] 2026년 일일동향보고 리스트`의 메타데이터·월별 탭·기존 행을 조회하지 않고 쓰기 도구도 호출하지 않는다. 나중에 운영 검증을 마친 뒤 설정이 명시적으로 `true`로 바뀌고 사용자가 결과 시트 반영을 요청한 실행에만 결과 월별 탭을 읽고 `scripts/sheet_sync_guard.py preflight --config <설정>`과 `scripts/sheet_sync_guard.py verify --config <설정>` 절차를 따른다. 이때도 입력 스프레드시트에는 쓰지 않으며, `append`만 쓰고 `no_op`은 생략하고 `conflict`는 자동 덮어쓰지 않는다.

## 금지

- 과거 샘플의 사람·조·담당 매핑 재사용
- 파일명 속 사람 이름만으로 작업조·담당까지 확정
- `0. 근무 일정` 시트의 `구분` 또는 작업자 이름을 작업조·초벌 담당·최종 담당 열에 그대로 복사
- `0. 근무 일정` 탭을 읽지 않고 과거 실행의 담당자나 요일 배정을 재사용
- 과거 실행의 `0. 근무 일정` 조회 범위·셀 주소·`동향스케줄.json`을 재사용하거나 `A1:L100` 같은 고정 좌표로 표 위치를 가정
- 비교 파일 경로를 주변 폴더에서 추측하거나 자동 선택
- 오전·오후·최종보고서 중 일부 필수 경로가 없는 상태로 실행
- 일본언론동향 원본을 찾지 못한 상태에서 일일일본동향을 일괄 X로 확정
- 일본 매체라는 이유만으로 일본동향 O 처리
- 카테고리나 매체명을 고정 사전으로 치환
- 정기·일본동향 → 오후폴더 → 오전폴더의 비교 단계를 실행별 `priority`나 파일명으로 뒤바꾸기
- 근거 없는 값을 빈칸 대신 임의로 채우기
- 필수 HWP·HWPX 또는 제공된 일본동향의 파싱 실패나 기사 0건을 경고로 낮춰 나머지 파일만으로 계속 처리
- `확인 필요` 행이 남은 결과를 Google Sheets에 업로드
- 중간 엑셀 생성 전에 Google Sheets 쓰기
- `sync.google_sheets_write_enabled`가 `false`인 상태에서 결과 스프레드시트 조회·쓰기 또는 `sheet_sync_guard.py` 실행
- 사용자의 명시적 결과 시트 반영 요청 없이 설정을 `true`로 바꾸거나 Google Sheets에 쓰기
- `process_job.py` 재실행 없이 `result.json`, 엑셀 또는 Google Sheets의 역할·분류·일본동향 값을 손으로 교정
- 동일 작업일의 서로 다른 기존 행 자동 교체

## 실행 예시

`<skill-root>`와 `<python-executable>`은 설치된 이 스킬과 Codex 워크스페이스 의존성의 실제 경로로 바꾼다. 결과 폴더를 생략하면 현재 작업 폴더의 `output/<작업일>`에 중간 저장한다.

```powershell
& "<python-executable>" "<skill-root>\scripts\select_schedule.py" `
  --input "근무시트_조회결과.json" --job-date "2026-07-23" `
  --spreadsheet-id "입력 문서에서 확인한 ID" --sheet-name "0. 근무 일정" `
  --range "현재 실행에서 조회한 실제 A1 범위" --heading "동향 스케줄" `
  --output "동향스케줄.json"

& "<python-executable>" "<skill-root>\scripts\prepare_source_history.py" `
  --input "작업내역_범위조회.json" --target-date "작업일 전날 YYYY-MM-DD" `
  --spreadsheet-id "입력 문서에서 확인한 ID" --sheet-name "1. 작업 내역" `
  --output "정기작업내역.json"

& "<python-executable>" "<skill-root>\scripts\discover_context.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --output "run_context.draft.json"

& "<python-executable>" "<skill-root>\scripts\process_job.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --run-context "run_context.json"
```

일본언론동향이 없는 작업일에는 두 명령의 `--japan-input` 줄을 생략한다.

# 외신동향 작업이력 하네스

## 원칙

현재 실행의 증거만 사용한다. 사람 이름, 작업조, 담당, 카테고리 목록, 매체 별칭을 설정이나 코드에 고정하지 않는다. 근거가 없으면 추측하지 않고 빈 값과 `확인 필요`를 남긴다. 스크립트는 추출·대조·검증을 담당하고, 의미와 역할 판정은 Codex가 매 실행 새로 수행한다.

작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자는 `외신 일일동향`의 `근무` 탭에 있는 `동향 스케줄`을 작업일 요일 기준으로 조회한 결과를 우선 근거로 삼는다. 다만 `근무` 시트의 `구분`과 작업자 이름을 결과 열에 그대로 복사하지 않는다. 근무표는 그날 각 업무를 맡은 사람을 확인하는 근거이고, 결과의 작업조·담당 표기는 현재 파일의 유입 단계와 업무 의미를 해석한 값이다. 시트의 사람 이름이나 사람별 역할은 코드에 복사하지 않고 매 실행 다시 읽는다.

## 필수 입력

- 오전 작업 폴더
- 오후 작업 폴더
- 최종보고서 파일
- 같은 작업일의 일본언론동향 원본 파일 경로
- Google Sheets `근무` 탭의 작업일 동향 스케줄

사용자는 오전 작업 폴더, 오후 작업 폴더, 최종보고서, 일본언론동향의 네 경로를 모두 정확하게 입력한다. 작업일은 최종보고서 본문과 파일명에서 자동 판정하며 서로 충돌하거나 판정할 수 없을 때만 사용자에게 확인한다. 비교 파일 경로는 추측하거나 주변 폴더에서 자동 탐색하지 않는다. 출력 폴더만 선택 입력이다.

## 사전 로드

1. 이 스킬 폴더의 `references/workflow-rules.md`와 `assets/harness.config.json`을 읽는다. `workflow-rules.md`는 업무 기준 원문이므로 사용자가 명시적으로 개정을 요청하지 않는 한 수정하지 않는다.
2. `references/schema.md`, `references/run-context.md`, `references/google-sheets.md`를 읽는다.
3. Google Sheets에는 `google-drive:google-sheets`, 엑셀에는 `spreadsheets:Spreadsheets` 스킬을 적용한다. 둘 중 하나가 없으면 대체 구현을 추측하지 말고 필요한 플러그인 설치를 안내한 뒤 중단한다.
4. 로컬 스크립트를 실행하기 전에 Codex 워크스페이스 의존성 경로를 불러온다. 모든 `.py` 파일은 반환된 Python 실행 파일로 실행한다. 모든 `.mjs` 파일은 반환된 Node.js 실행 파일로 실행하고, 반환된 Node.js packages 경로를 해당 명령의 `NODE_PATH`로 설정한다. 사용자의 Python·Node.js 설치를 가정하거나 전역 환경 변수·프로젝트 `node_modules`를 만들지 않는다.

## 실행

1. 최종보고서 본문과 파일명에서 작업일 후보와 근거를 추출한다.
2. 연결 계정과 스프레드시트를 확인하고 `작업내역`에서 작업일 전날 행만 읽어 `정기작업내역.json`으로 저장한다.
3. 같은 스프레드시트의 `근무` 탭을 읽어 로컬에 보존하고, `scripts/select_schedule.py`로 작업일의 요일 열만 선택해 `동향스케줄.json`을 만든다. 표의 보고서·구분·담당자 셀을 그대로 보존하며 사람별 역할 매핑을 만들지 않는다.
4. 사용자가 입력한 네 경로의 존재 여부와 파일 형식을 검사한다. 일본언론동향과 최종보고서의 작업일이 다르면 중단한다.
5. `scripts/discover_context.py`를 `--schedule-json 동향스케줄.json` 및 명시된 일본동향과 함께 실행해 현재 입력의 파일명, 경로, 문서 미리보기, 기사 수, SHA-256과 입력 지문을 `run_context.draft.json`에 수집한다.
6. Codex가 초안과 현재 문서·스케줄을 직접 비교해 `run_context.json`을 작성한다. 먼저 현재 파일을 개별 초안, 정기 유입, 일본언론동향 같은 특수 유입, 오후 취합본, 오전 총괄본으로 구분한다. 오전·오후 폴더명은 보관 단계일 뿐 작업조 값으로 복사하지 않는다. 정기·일본동향은 `workgroup`에 유입 경로를 기록하고, `owner`·`worker`에는 해당 경로의 기사를 당일 실제 편집한 단계와 작업자를 기록한다. 작업자 이름은 같은 역할의 당일 `근무` 행과 파일명을 대조해 확정한다. 최종보고서 대표 기사의 최종 담당은 사람 이름이 아니라 최종 총괄 단계 표기이며, 최종 작업자는 가장 늦은 파일명이 아니라 최종 대표본을 실제 편집한 당일 총괄 작업자다. 다섯 역할 열의 판단에는 반드시 유효한 `schedule_refs`를 넣고, 구체적인 파일·시트 근거를 `evidence`에 기록한다. 실제 초벌 파일만 `include_unmatched: true`로 표시하고 취합본·중간 총괄본은 제외한다. 일본동향 제공 여부와 비대표 기사의 최종 담당 표기도 근거가 있을 때만 확정한다. 이전 실행 컨텍스트는 복사하지 않는다.
7. 유입 경로가 서로 겹치면 모든 작업본을 하나의 경로로 취급하지 않는다. 현재 파일들의 최초 유입·취합 순서를 비교해 개별 초안, 정기, 특수 자료, 취합본별 `priority`를 실행마다 따로 매기고, 경로 사이에 단계가 섞여야 하면 `origin_policy.selection: priority_then_score`를 사용한다. 이 숫자는 사람별 고정값이 아니라 현재 실행의 상대 순서다.
8. 이 스킬 폴더의 `scripts/process_job.py --run-context <경로>`를 실행한다. 별도 설정을 지정하지 않으면 스크립트가 `assets/harness.config.json`을 사용한다. 컨텍스트 작성 후 일본언론동향을 포함한 입력 파일이 바뀌면 중단하고 다시 판단한다.
9. 일본언론동향 원본과 최종 결과를 제목·매체·날짜로 비교한다. 제목이 크게 바뀌었지만 원문상 동일한 기사는 `article_japan_confirmations`에 현재 실행의 원문 대조 근거를 기록해 O로 확정한다.
10. 최종보고서 대표·유사 기사에 실제 초벌 작업본의 완전 미포함(X/X) 기사를 더한 수와 결과 행 수가 같은지 확인한다. 첫 장의 `/` 묶음은 첫 매체를 대표로, 뒤 매체 기사를 유사보도로 유지한다. 유사보도 제목 줄의 날짜가 비어 있으면 매칭된 현재 원본 날짜를 사용한다. 낮은 매칭 점수나 불완전한 역할 근거는 결과에서 제거하지 않고 `확인 필요`로 분리한다.
11. 사용자가 같은 작업일의 권위 있는 정답 파일을 제공하면 `xlsx_to_json.mjs`로 읽은 뒤 `apply_reference_feedback.py`로 역할·표기·행 순서 차이를 해시 검증된 실행별 확인값으로 만든다. 자동 결과에 없는 유사·미포함 행만 현재 원본 후보를 직접 대조해 `article_additions`로 보완한다. 기준 파일 경로와 SHA-256, 현재 원본의 정확한 유입 경로·제목, 삽입 위치, 구체적 행 근거를 모두 기록하고 다른 날짜에는 재사용하지 않는다. 재실행 후 `compare_reference_result.py`의 `exact_match`를 확인한다.
12. `scripts/build_workbooks.mjs`로 `작업이력_중간저장.xlsx`와 `확인필요_목록.xlsx`를 먼저 생성하고 모든 시트를 렌더링 검수한다. 엑셀 생성이 끝나기 전에는 Google Sheets에 쓰지 않는다.
13. 월별 결과 탭을 읽어 `scripts/sheet_sync_guard.py preflight`를 실행한다. `append`만 쓰고, `no_op`은 생략하며, `conflict`는 자동 덮어쓰지 않는다.
14. 쓴 범위를 재조회해 `scripts/sheet_sync_guard.py verify`로 완전 일치를 확인한 뒤 `작업이력_최종.xlsx`를 만든다.

## 금지

- 과거 샘플의 사람·조·담당 매핑 재사용
- 파일명 속 사람 이름만으로 작업조·담당까지 확정
- `근무` 시트의 `구분` 또는 작업자 이름을 작업조·초벌 담당·최종 담당 열에 그대로 복사
- `근무` 탭을 읽지 않고 과거 실행의 담당자나 요일 배정을 재사용
- 비교 파일 경로를 주변 폴더에서 추측하거나 자동 선택
- 오전·오후·최종보고서·일본언론동향 중 일부 경로가 없는 상태로 실행
- 일본언론동향 원본을 찾지 못한 상태에서 일일일본동향을 일괄 X로 확정
- 일본 매체라는 이유만으로 일본동향 O 처리
- 카테고리나 매체명을 고정 사전으로 치환
- 근거 없는 값을 빈칸 대신 임의로 채우기
- 중간 엑셀 생성 전에 Google Sheets 쓰기
- 동일 작업일의 서로 다른 기존 행 자동 교체

## 실행 예시

`<skill-root>`와 `<python-executable>`은 설치된 이 스킬과 Codex 워크스페이스 의존성의 실제 경로로 바꾼다. 결과 폴더를 생략하면 현재 작업 폴더의 `output/<작업일>`에 중간 저장한다.

```powershell
& "<python-executable>" "<skill-root>\scripts\select_schedule.py" `
  --input "근무시트_조회결과.json" --job-date "2026-07-23" `
  --output "동향스케줄.json"

& "<python-executable>" "<skill-root>\scripts\discover_context.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --output "run_context.draft.json"

& "<python-executable>" "<skill-root>\scripts\process_job.py" `
  --morning-dir "오전폴더" --afternoon-dir "오후폴더" `
  --final-report "최종보고서.hwpx" --source-json "정기작업내역.json" `
  --schedule-json "동향스케줄.json" `
  --japan-input "일본언론동향.hwpx" `
  --run-context "run_context.json"
```

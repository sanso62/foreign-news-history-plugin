# Google Sheets 입력 조회와 선택적 결과 동기화

## 현재 운영 모드

`assets/harness.config.json`의 `sync.google_sheets_write_enabled` 기본값은 `false`다. 이 상태에서는 입력 스프레드시트의 `1. 작업 내역`과 `0. 근무 일정`만 읽고, 결과 스프레드시트 `[VT] 2026년 일일동향보고 리스트`는 메타데이터·월별 탭·기존 행을 포함해 조회하거나 쓰지 않는다. 최종 산출물은 로컬 `작업이력_최종.xlsx`다.

작업자 시험 운영이 끝난 뒤 이 설정을 명시적으로 `true`로 바꾸고 사용자가 결과 시트 반영을 요청한 실행에서만 아래 결과 동기화 절차를 사용한다. `scripts/sheet_sync_guard.py`도 설정이 `true`가 아니면 `preflight`와 `verify`를 모두 거부한다.

## 대상

- 입력 스프레드시트: `[VT] 2026년 24시간 외신 모니터링 및 요약 보고`, 읽기 전용
- 정기 작업 탭: `1. 작업 내역`, `A:O` 읽기 전용
- 근무 일정 탭: `0. 근무 일정`, 읽기 전용. 고정 범위를 사용하지 않고 매 실행 현재 그리드에서 `동향 스케줄` 제목과 표 헤더를 찾아 작업일 요일의 담당자 근거를 조회
- 선택적 결과 스프레드시트: `[VT] 2026년 일일동향보고 리스트`
- 선택적 결과 탭: 작업일의 월을 사용한 `{month}월`, `A:O`

두 문서는 별개다. 기본 엑셀 전용 실행에서는 연결 프로필과 입력 스프레드시트 메타데이터만 읽는다. 결과 쓰기가 활성화된 실행에서만 결과 스프레드시트 메타데이터도 다시 읽고 제목·ID·탭·헤더가 맞는지 확인한다. 배포본 설정에는 문서 ID나 URL을 넣지 않고 정확한 제목과 구조로 연결 문서를 찾는다. 같은 제목의 후보가 여러 개면 `1. 작업 내역`에 `작업날짜`·`작업 조`·`보도일`·`제목 (한글)` 헤더가 함께 있고 `0. 근무 일정`에 현재 `동향 스케줄`이 있는 운영 문서만 입력으로 인정하며, 하나로 확정할 수 없으면 중단한다.

## 읽기

입력 전체 시트를 무제한으로 가져오지 않는다. 메타데이터의 실제 그리드 행 수와 `A:O` 15열을 기준으로 한 번에 5만 셀 이하인 겹치지 않는 유한 A1 범위를 만든다. 각 범위를 반드시 `FORMATTED_VALUE`로 읽고 원시 응답의 실제 `range`와 `values`를 로컬 JSON에 보존한다. `search_spreadsheet_rows`의 날짜 문자열 검색으로 대상 행을 수집하지 않는다. 표시값이 `2026. 7. 22`인데 `2026-07-22`를 검색하면 날짜 셀은 빠지고 URL에 해당 문자열이 든 일부 행만 남을 수 있기 때문이다.

모든 범위의 헤더와 행을 원본 순서로 합친 뒤 `scripts/prepare_source_history.py`에 작업일 전날 ISO 날짜를 전달한다. 이 스크립트가 표시 날짜를 로컬에서 파싱해 대상 행만 고르고, `source_audit`에 `bounded_range_scan`, `FORMATTED_VALUE`, 실제 스캔 범위, 스캔·일치 행 수를 기록한 `정기작업내역.json`을 만든다. 감사정보가 없거나 날짜 검색 결과인 입력은 `process_job.py`가 거부한다.

`0. 근무 일정` 탭은 매 실행 먼저 메타데이터로 실제 탭 이름, `sheetId`, 그리드 행·열 수를 확인한다. 메타데이터가 가리키는 그리드를 `assets/harness.config.json`의 `schedule_scan_max_cells` 이하 청크로 나누어 `동향 스케줄`과 정확히 일치하는 셀을 찾는다. 청크는 서로 겹치지 않게 조회하고 빈 검색어나 전체 그리드 단일 조회를 사용하지 않는다. 제목 셀을 찾으면 그 주변의 작은 범위를 읽어 아래쪽에 `보고서`, `구분`, 최종보고서 작업일의 요일, 최소 5개의 요일 헤더가 함께 있는지 확인한다. 유효한 표가 없거나 둘 이상이면 범위를 추측하지 않고 중단한다.

확인된 표 범위와 해당 조회 응답을 로컬 JSON에 보존하고, 최종보고서 작업일로 요일을 계산해 `scripts/select_schedule.py`에 정확한 A1 조회 범위를 전달한다. 선택 결과에는 입력 스프레드시트 ID, 탭, 실제 조회 범위, 표 제목·헤더 셀, 원본 행 번호와 보고서·구분·발행 요일·담당자 셀을 보존한다. `scripts/process_job.py`는 이 동적 출처 정보가 없거나 설정된 입력 문서·탭과 다른 스케줄 JSON을 거부한다. 이 자료는 작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자의 필수 근거이며 입력 문서의 `1. 작업 내역` 및 `0. 근무 일정` 탭에는 쓰지 않는다.

## 선택적 쓰기 전 검사

이 절은 `sync.google_sheets_write_enabled: true`이고 사용자가 결과 시트 반영을 명시적으로 요청한 실행에만 적용한다.

1. 로컬 중간 엑셀과 `checkpoint.json`의 `intermediate_saved`를 확인한다.
2. `checkpoint.json`의 `review_rows`가 0인지 확인한다. 한 건이라도 남아 있으면 쓰기를 중단한다.
3. 월별 탭 `A1:O1`이 결과 스키마와 정확히 같은지 확인한다.
4. 월별 탭에서 같은 작업일 행을 조회한다.
5. 기존 행이 없으면 추가한다.
6. 기존 행이 새 결과와 같으면 쓰지 않고 성공으로 기록한다.
7. 기존 행이 새 결과와 다르면 자동 수정·삭제하지 않고 사용자 승인 요청으로 중단한다.

## 선택적 쓰기와 검증

헤더는 쓰지 않고 데이터 행만 한 번의 연속 범위로 추가한다. 쓰기 직후 해당 범위를 재조회하여 행 수와 모든 `A:O` 값을 비교한다. 정확히 같을 때만 체크포인트를 `uploaded_verified`로 변경한다.

입력 문서의 `1. 작업 내역`과 `0. 근무 일정`에는 어떠한 쓰기·정렬·서식 변경도 하지 않는다. 결과 쓰기가 활성화된 경우에도 결과 문서 `[VT] 2026년 일일동향보고 리스트`의 검증된 월별 탭에만 수행한다.

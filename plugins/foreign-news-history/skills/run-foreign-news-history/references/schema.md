# 입출력 스키마

## 정기 작업내역 JSON

다음 중 하나를 허용한다.

- `{"values": [[헤더...], [행...]]}` 형태의 2차원 배열
- `[{"보도일": "...", ...}]` 형태의 행 객체 배열

필수 원본 헤더는 다음 11개다.

1. 보도일
2. 보도시각 (KST)
3. URL (단축)
4. 온라인 기사 URL
5. 매체국가
6. 매체명 (원어)
7. 매체명 (한글)
8. 발신지
9. 언어
10. 기자명
11. 제목 (한글)

## 결과 열

Google Sheets와 엑셀의 열 순서는 정확히 다음 `A:O`를 사용한다.

1. 상계월
2. 작업일
3. 작업조
4. 초벌 담당
5. 초벌 작업자
6. 최종 담당
7. 최종 작업자
8. 카테고리
9. 매체명
10. 날짜
11. 제목
12. 최종 보고서 포함 여부
13. 유사보도 여부
14. 일일일본동향
15. 비고

## 체크포인트

출력 폴더에 다음 파일을 둔다.

- `manifest.json`: 입력 파일, 크기, SHA-256
- `result.json`: 헤더와 결과 행
- `review.json`: 확인 필요 행과 사유
- `google_payload.json`: 그대로 업로드 가능한 `A:O` 2차원 배열
- `checkpoint.json`: `local_processed`, `intermediate_saved`, `uploaded_verified` 단계
- `작업로그.txt`: 실행 요약과 경고
- `run_context.json`: 현재 입력과 당일 근거만으로 작성한 작업자·역할 판단 기록
- `동향스케줄.json`: `근무` 탭에서 작업일 요일 열을 선택한 보고서·구분·담당자 및 원본 행·셀 근거

`intermediate_saved` 전에는 Google Sheets에 쓰지 않는다.

사람·작업조·담당·카테고리·매체 별칭은 이 스키마나 전역 설정에 저장하지 않는다. 현재 실행의 판단은 `references/run-context.md` 구조를 따른다.

작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자의 프로필은 `동향스케줄.json`에 실제 존재하는 `schedule_refs`가 있을 때만 완전한 근거로 인정한다.

일본언론동향 파일은 입력 지문과 `manifest.json`에 포함한다. 원본 수록 기사는 결과 14열 `일일일본동향`에 `O`, 비수록 기사는 공란으로 기록하며 `X`를 채우지 않는다. 자동 매칭이 어려운 동일 기사 확인은 실행별 `article_japan_confirmations`에만 저장한다.

결과 행은 최종보고서 대표 기사와 유사보도뿐 아니라, 실행 컨텍스트에서 실제 초벌 파일로 확인된 작업본 전용 X/X 기사도 포함할 수 있다. 취합본·중간 총괄본은 X/X 후보 원본으로 사용하지 않는다.

유사보도의 최종 제목 줄에 날짜가 없으면 매칭된 현재 원본의 날짜를 사용하고, 모든 현재 원본에도 날짜가 없을 때만 `없음`을 쓴다. 사용자가 제공한 같은 작업일의 해시 검증된 기준표에서만 확인되는 추가 유사·미포함 행은 `article_additions`로 기록하며, 다른 실행으로 승계하지 않는다.

## 매칭 우선순위

최종보고서의 유입 경로 비교 단계는 휴먼 업무 절차에 따라 고정한다.

1. Google Sheets 정기 작업내역과 사용자가 지정한 일본언론동향 원본
2. 오전폴더
3. 오후폴더

1단계에서 양쪽이 모두 일치하면 정기 경로를 선택하고 `일일일본동향`은 O로 유지한다. 현재 단계에서 `review_threshold` 이상의 후보를 찾으면 뒤 단계의 더 높은 점수나 `priority`가 선택을 덮어쓰지 못한다. `priority`는 같은 비교 단계 안에서 현재 파일의 최초 유입·취합 관계를 구분하는 보조값일 뿐이며 사람별 고정 순위가 아니다. 오전·오후 단계는 사용자가 지정한 실제 입력 폴더로 판정한다.

같은 단계 안에서 둘 이상의 경로가 기준을 넘고 근거가 경합하면 `비고`에 `확인 필요` 사유를 적는다. 점수가 자동판정 기준보다 낮거나 같은 단계 후보 간 차이가 `ambiguity_margin`보다 작을 때도 결과를 제거하지 않고 검수 대상으로 유지한다. 현재 원문을 직접 대조한 실행별 `article_origin_confirmations`만 자동 선택을 교정할 수 있다.

# 입출력 스키마

## 정기 작업내역 JSON

운영 실행에서는 `scripts/prepare_source_history.py`가 만든 다음 구조를 사용한다.

- `source_audit`: 스키마 버전 2, `bounded_range_scan`, `FORMATTED_VALUE`, 스프레드시트·탭·실제 유한 A1 범위, 대상일, 스캔·일치 행 수
- `values`: `[[헤더...], [대상일 행...]]` 형태의 2차원 배열

내부 유틸리티는 기존 `values` 배열이나 행 객체 배열도 읽을 수 있지만, 설정의 `require_source_scan_audit`가 켜진 운영 실행에서는 감사정보 없는 입력을 거부한다.

필수 원본 헤더는 다음 11개다.

1. 보도일
2. 보도시각 (KST)
3. URL (단축)
4. 온라인 기사 URL
5. 매체국가
6. 매체명 (원어)
7. 매체명 (한글)
8. 발신지
9. 언어
10. 기자명
11. 제목 (한글)

## 결과 열

Google Sheets와 엑셀의 열 순서는 정확히 다음 `A:O`를 사용한다.

1. 상계월
2. 작업일
3. 작업조
4. 초벌 담당
5. 초벌 작업자
6. 최종 담당
7. 최종 작업자
8. 카테고리
9. 매체명
10. 날짜
11. 제목
12. 최종 보고서 포함 여부
13. 유사보도 여부
14. 일일일본동향
15. 비고

## 체크포인트

출력 폴더에 다음 파일을 둔다.

- `manifest.json`: 입력 파일, 크기, SHA-256
- `result.json`: 헤더와 결과 행
- `review.json`: 확인 필요 행과 사유
- `google_payload.json`: 그대로 업로드 가능한 `A:O` 2차원 배열
- `checkpoint.json`: `local_processed`, `intermediate_saved`, `uploaded_verified` 단계
- `작업로그.txt`: 실행 요약과 경고
- `run_context.json`: 현재 입력과 당일 근거만으로 작성한 작업자·역할 판단 기록
- `동향스케줄.json`: 매 실행 `근무` 탭의 현재 그리드에서 `동향 스케줄` 제목과 헤더를 동적으로 찾은 뒤 작업일 요일 열을 선택한 보고서·구분·담당자 및 원본 행·셀 근거. 스키마 버전 2이며 실제 조회 범위, `heading_cell`, `header_cell`, 각 행의 `report_cell`, `division_cell`, `publication_schedule_cell`, `worker_cell`을 포함한다.

`intermediate_saved` 전에는 Google Sheets에 쓰지 않는다.
`checkpoint.json`의 `review_rows`가 0이 아니면 Google Sheets에 쓰지 않는다. 현재 원문이나 같은 작업일의 해시 검증된 기준표 확인값으로 보완한 뒤 결과와 중간 엑셀을 다시 생성한다.

사람·사람별 작업조·담당·카테고리·매체 별칭은 이 스키마나 전역 설정에 저장하지 않는다. 업무 프롬프트에 명시된 파일 단계별 역할 표기는 허용되는 판정 규칙이며, 현재 실행의 사람은 `references/run-context.md` 구조에 따라 파일명과 당일 근무표로 확인한다.

작업조·초벌 담당·초벌 작업자·최종 담당·최종 작업자의 프로필은 `동향스케줄.json`에 실제 존재하는 `schedule_refs`가 있을 때만 완전한 근거로 인정한다.

일본언론동향 파일은 입력 지문과 `manifest.json`에 포함한다. 원본 수록 기사는 결과 14열 `일일일본동향`에 `O`, 비수록 기사는 공란으로 기록하며 `X`를 채우지 않는다. 자동 매칭이 어려운 동일 기사 확인은 실행별 `article_japan_confirmations`에만 저장한다. 일본동향 전체 기사 묶음을 가장 많이 일치시킨 당일 작업본의 역할·작업자를 묶음 전체의 초벌 담당·작업자로 사용하며 기사별로 서로 다른 담당자를 만들지 않는다.

결과 행은 최종보고서 대표 기사와 유사보도뿐 아니라, 실행 컨텍스트에서 실제 초벌 파일로 확인된 작업본 전용 X/X 기사도 포함할 수 있다. 오후 취합본의 기사가 오전 취합본까지 유지됐다가 최종에서 빠진 경우도 X/X로 포함하며 `1조/오후/총괄` 역할을 사용한다. 한 단계 취합본에만 잠시 나타난 기사는 X/X 후보로 자동 추가하지 않는다.

유사보도의 최종 제목 줄에 날짜가 없으면 매칭된 현재 원본의 날짜를 사용하고, 모든 현재 원본에도 날짜가 없을 때만 `없음`을 쓴다. 사용자가 제공한 같은 작업일의 해시 검증된 기준표에서만 확인되는 추가 유사·미포함 행은 `article_additions`로 기록하며, 다른 실행으로 승계하지 않는다.

## 매칭 우선순위

최종보고서의 유입 경로 비교 단계는 휴먼 업무 절차에 따라 고정한다.

1. Google Sheets 정기 작업내역과 사용자가 지정한 일본언론동향 원본
2. 전일 밤 오후폴더
3. 당일 새벽 오전폴더

1단계에서 양쪽이 모두 일치하면 정기 경로를 선택하고 `일일일본동향`은 O로 유지한다. `auto_threshold`에 도달한 1단계 후보는 뒤 단계의 복사본보다 우선한다. 1단계 후보가 자동 기준 미만일 때만, `auto_threshold` 이상의 현재 개별 국내·글로벌 초안이 `ambiguity_margin` 이상 강하면 기사 단위 직접 초벌 근거로 선택한다. 1단계 후보가 `review_threshold` 미만이고 개별 초안은 그 이상이면서 같은 여유폭 이상 우세한 경우도 별도 낮은 점수 경고 없이 초안 유입을 확정한다. 직접 확인된 일본 원문은 크게 바뀐 정기 제목 추정보다 우선한다. 그 밖에는 뒤 단계의 더 높은 점수나 `priority`가 앞 단계 선택을 덮어쓰지 못한다. `priority`는 같은 비교 단계 안에서 개별 초안을 취합·총괄본보다 먼저 보기 위한 보조값일 뿐이며 사람별 고정 순위가 아니다. 오전·오후 단계는 사용자가 지정한 실제 입력 폴더로 판정한다.

같은 단계 안에서 둘 이상의 경로가 기준을 넘고 근거가 경합하면 `비고`에 `확인 필요` 사유를 적는다. 점수가 자동판정 기준보다 낮거나 같은 단계 후보 간 차이가 `ambiguity_margin`보다 작을 때도 결과를 제거하지 않고 검수 대상으로 유지한다. 현재 원문을 직접 대조한 실행별 `article_origin_confirmations`만 자동 선택을 교정할 수 있다.
